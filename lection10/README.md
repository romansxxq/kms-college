### 1. Схема послідовності обробки переривання:

```mermaid
sequenceDiagram
    autonumber
    participant HW as Контролер пристрою
    participant CPU as Процесор (ЦП)
    participant ISR as Обробник переривання

    HW->>CPU: Апаратний сигнал переривання (наприклад, натискання клавіші)
    Note over CPU: Завершення поточної команди
    Note over CPU: Збереження контексту в стек (PC, прапорці, регістри)

    CPU->>ISR: Перехід за вектором з таблиці IVT (наприклад, int 9h)
    activate ISR
    Note over ISR: Виконання коду обробника (наприклад, in al, 60h)

    ISR-->>CPU: Команда IRET (повернення з переривання)
    deactivate ISR

    Note over CPU: Відновлення контексту зі стека
    Note over CPU: Продовження виконання перерваної програми
```
### 2.
* а) Натискання клавіші на клавіатурі: Апаратне переривання (асинхронний зовнішній сигнал від контролера).
* б) Спроба ділення числа на нуль: Виняток (exception / fault) (помилка виконання арифметичної команди).
* в) Зупинка програми на точці зупинки в дебагері: Пастка (trap) (навмисне програмне переривання/breakpoint).

### 3. Пояснення щодо довгого читання з диска:

Читання з накопичувача вимагає мільйонів тактів очікування. Якщо виконувати його всередині обробника, процесор заблокує інші переривання, через що система втратить нові події від клавіатури, таймера чи мережі.

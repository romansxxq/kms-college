## 1. Переведення числа -19 у 8-бітний додатковий код

1. Запишемо модуль числа 19 у двійковій системі:

	 `19 = 00010011`

	 Пряме представлення від’ємного числа (старший біт є знаковим):

	 `-19 = 10010011`

2. Знайдемо обернений код: інвертуємо всі біти прямого представлення:

	 `10010011 -> 01101100`

3. Додамо одиницю до оберненого коду:

	 ```text
		 01101100
	 + 00000001
	 ----------
		 01101101
	 ```

Отже, 8-бітний додатковий код числа `-19` — `11101101`.

## 2. Додавання в додатковому коді

```text
	01111000   (120)
+ 00010101   (21)
----------
	10001101
```

Результат у 8 бітах — `10001101`. Оскільки старший біт дорівнює `1`, цей запис як знакове число є від’ємним. Але обидва доданки додатні, а математична сума дорівнює `120 + 21 = 141`.

Для 8-бітного додаткового коду діапазон знакових чисел становить від `-128` до `127`, тому `141` подати неможливо. Виникло **переповнення**.

Ознака переповнення: додавання двох чисел з однаковими знаками дало результат з іншим знаком. Додатні доданки (`0` у старшому біті) дали результат зі старшим бітом `1`.

## 3. Число 12.5 у форматі IEEE 754 single precision

Переведемо число у двійкову систему:

```text
12.5 = 1100.1₂ = 1.1001₂ × 2³
```

- **Знак:** `0`, оскільки число додатне.
- **Нормалізований порядок:** `3`; у полі експоненти зсунутий порядок дорівнює `3 + 127 = 130`, тобто `10000010₂`.
- **Мантиса:** після початкової одиниці записується `1001`, а решта бітів заповнюється нулями: `10010000000000000000000`.

Повний запис має вигляд:

```text
0 | 10000010 | 10010000000000000000000
```

Якщо під «порядком» мається на увазі найближча ціла степінь двійки, то `12.5` ближче до `16 = 2⁴`, ніж до `8 = 2³`. Водночас у нормалізованому представленні IEEE 754 використовується показник `3`, бо `12.5 = 1.1001₂ × 2³`.

Число `12.5` представляється точно, тому що його двійковий запис є скінченним: `1100.1₂`. У single precision усі його значущі біти вміщуються в поле мантиси.

Число `0.1` у двійковій системі має нескінченний періодичний запис:

```text
0.1₁₀ = 0.00011001100110011...₂
```

Тому в 32 бітах зберігається лише округлене наближення, а не точне значення `0.1`.

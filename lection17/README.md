### 1. Триетапне рукостискання TCP

За умовою початковий номер послідовності клієнта — **1000**, сервера — **2000**. Розглядаю звичайне встановлення з'єднання без передавання даних у цих трьох сегментах.

| Крок | Напрямок | Прапорці | seq | ack |
|---|---|---|---:|---|
| 1 | Клієнт → сервер | SYN | 1000 | 0, не використовується |
| 2 | Сервер → клієнт | SYN, ACK | 2000 | 1001 |
| 3 | Клієнт → сервер | ACK | 1001 | 2001 |

1. Клієнт надсилає **SYN** і повідомляє свій початковий `seq = 1000`. Прапорець ACK ще не встановлений, тому поле підтвердження не має значення.
2. Сервер відповідає **SYN, ACK**: передає власний `seq = 2000` і підтверджує SYN клієнта значенням `ack = 1000 + 1 = 1001`.
3. Клієнт надсилає **ACK** із `seq = 1001` і `ack = 2000 + 1 = 2001`, підтверджуючи SYN сервера.

SYN займає одну позицію в просторі номерів послідовності, навіть якщо не містить прикладних даних. Тому до початкових номерів додається 1. Звичайний ACK без даних сам по собі номер послідовності не збільшує.

### 2. Вибір між TCP і UDP

| Сценарій | Протокол | Обґрунтування |
|---|---|---|
| Завантаження вебсторінки | TCP для HTTP/1.1 і HTTP/2 | Потрібно отримати документ, стилі й скрипти повністю та без порушення порядку байтів. TCP забезпечує повторне передавання втрачених даних. |
| VoIP-телефонія | UDP для голосового потоку | Важлива мала затримка: запізнілий фрагмент розмови часто вже не потрібний. Невелику втрату пакетів краще обробити, ніж чекати повторного передавання. |
| Онлайн-гра в реальному часі | UDP для поточних ігрових подій | Нові координати й дії швидко замінюють старі, тому актуальність важливіша за повторне доставлення застарілого стану. |
| Передавання файлу по FTP | TCP | Файл має надійти повністю й без пропусків. FTP використовує TCP як для керування, так і для передавання даних. |

Для вебсторінок є уточнення з наступної теми: **HTTP/3 використовує QUIC поверх UDP**, тому не кожен сучасний HTTPS-запит працює через TCP.

### 4. Підготовка до наступного заняття: DNS

Браузер дізнається IP-адресу за доменом через DNS: спочатку можуть використовуватися кешовані дані, а за їхньої відсутності виконується запит до DNS-резолвера. Записи A містять IPv4-адреси, AAAA — IPv6-адреси.

Якщо DNS-сервер не відповідає й потрібної адреси немає в кеші, браузер не зможе визначити адресу сервера та відкрити сайт за цим ім'ям. При цьому сам сайт і мережеве з'єднання можуть працювати — проблема буде саме в розв'язанні доменного імені.

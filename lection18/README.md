### 1. DNS-запит для github.com

У командному рядку виконав:

```powershell
nslookup github.com
```

Фрагмент отриманої відповіді:

```text
Server:  UnKnown
Address:  192.168.1.1

Name:    github.com
Address:  140.82.121.4
```

Отримано **один A-запис: github.com → 140.82.121.4**. Запит обробив локальний DNS-сервер **192.168.1.1**.

У звичайному виводі TTL не показано. Додатково виконав команду:

```powershell
nslookup -debug -type=A github.com
```

Для A-запису вона показала:

```text
ANSWERS:
->  github.com
internet address = 140.82.121.4
ttl = 36 (36 secs)
```

Отже, під час перевірки **TTL становив 36 секунд**. Це час життя відповіді, повернутої резолвером; для кешованого запису він поступово зменшується. Результат зафіксовано 28.10.2026.

### 2. Отримання адреси ноутбуком: послідовність DORA

Після підключення до нової Wi-Fi мережі ноутбук ще не має робочої IPv4-адреси, тому використовує DHCP.

| Крок | Надсилач → отримувач | Що відбувається |
|---|---|---|
| **Discover** | Ноутбук → DHCP-сервери в локальній мережі | Клієнт надсилає широкомовний запит на `255.255.255.255`, щоб знайти сервер. Адреса джерела — `0.0.0.0`. |
| **Offer** | DHCP-сервер → ноутбук | Сервер пропонує IP-адресу, маску, шлюз, DNS-сервери й термін оренди. Залежно від можливостей клієнта відповідь може бути широкомовною. |
| **Request** | Ноутбук → DHCP-сервери | Ноутбук широкомовно повідомляє, яку пропозицію й якого сервера обрав. Інші сервери бачать, що їхні пропозиції не прийнято. |
| **Acknowledge** | Обраний DHCP-сервер → ноутбук | Сервер підтверджує видачу адреси та мережевих налаштувань на певний термін. Ноутбук може завершити налаштування інтерфейсу. |

Адреса видається не назавжди, а на час **лізингу**. Для її подальшого використання клієнт поновлює оренду; за успішного поновлення повторювати весь пошук Discover не потрібно.

### 3. Помилка у твердженні про GET і форму реєстрації

Твердження «HTTP-запит GET використовується для надсилання форми реєстрації користувача на сервер» неправильне, тому що **GET призначений для отримання ресурсу**, а реєстрація створює нового користувача й змінює стан сервера.

Для надсилання такої форми використовують **POST**: дані передаються в тілі запиту. У GET параметри потрапляють до URL і можуть залишитися в історії браузера та журналах сервера, тому передавати так пароль не слід.

Сам POST не шифрує інформацію. Для захисту даних реєстрації потрібно використовувати **HTTPS**.
